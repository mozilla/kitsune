# wiki — Knowledge Base

KB articles (`Document`) with revisions, translations, and wiki-markup rendering.

- **Parser:** `parser.py` renders wiki markup → HTML. `wiki_to_html()` is the entry point; `WikiParser.expand_fors()` renders `{for platform,version}` show-for blocks as `<div|span class="for" data-for="...">`, stored on `Document.html`. Show-for scope is subtle — a section can be conditional on platform / version / product.
- **Audiences:** read access lives on originals (`Document.audiences`); translations inherit it and never get rows. An audience is a knowledge base; an original assigned any public one (`is_public`) is readable by everyone. The default KB is the reserved slug `default` and is always public. An original with no audience is readable by Staff and superusers only. Check read access through `visible()` / `is_visible_for()` / `audience_access()`.
- **Images:** every gallery `Image` belongs to one KB (`Image.audience`, chosen at upload; an upload outside a private KB lands in the default KB). Rules every new code path must keep:
  - Listings and the API go through `Image.objects.public()` (images of public KBs); the picker lists a private KB's images with `private_in()`. Articles in exactly one private KB resolve `[[Image:title]]` in that KB first, then in the default KB; everything else — several private KBs, public articles, forums, questions — uses `Image.objects.in_default_kb()`. `Image.objects.all()` / `.filter()` on a user-facing path leaks private titles and thumbnails: use `public()`, `private_in()`, `in_default_kb()` or `Image.is_readable_by(user)`. Load an image with `select_related("audience")` before `is_private` / `is_readable_by`: both read `audience.is_public`, so a public image costs no access query.
  - File names under `private/` route to `private_storage()` (`kitsune/gallery/storage.py`): GCS bucket `GS_PRIVATE_BUCKET_NAME` (must differ from `GS_BUCKET_NAME`) or, on the filesystem, `PRIVATE_MEDIA_ROOT`. On S3 or without a private bucket private images are off: uploads to a private KB are rejected, their pages and files 404. The only URL the app emits for a private file is `/private-media/<name>`, served after `is_readable_by`; a thumbnail's location follows its source file's name.
  - Titles are unique per `(locale, title, audience)`. Making a KB public keeps its images readable by anyone through `/private-media/`, but they stop rendering in its articles (those resolve in the default KB now); the admin asks for confirmation.
- **Translations:** an article and its localized versions form a family. `Document.parent_id` links a translation to its English parent; `Document.translated_to(locale)` resolves a locale variant.
- **Currency:** `Document.is_outdated(level)` compares a translation against its parent's significant revisions (MEDIUM / MAJOR) — a translation can be stale without being wrong.
- **Scheduled publishing:** a revision with a `ScheduledRevision` stays unreviewed (`is_approved=False`, `reviewed=None`) until the release task applies the stored review.
- Rendering must be **faithful** — don't "clean up" parser output (e.g. spacing around punctuation); it corrupts locale typography.
